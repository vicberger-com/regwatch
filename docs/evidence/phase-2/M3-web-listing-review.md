## Data flows touched
- **Worker to the listing page's host:** one `GET page_url` through `ctx.fetcher` with the job's rate and robots override. The answer must be 2xx HTML.
- **Worker to the extraction child:** the listing body, the charset and `links_selector`. The answer gains `links`: at most 2,000 hrefs as written, each at most 2,048 characters, checked by `_answer`.
- **Listing to candidates:** each href is resolved by `entry_link` against the final URL (http or https, no userinfo, public literal addresses only, no numeric or local names, no controls, fragment dropped, query kept, at most `MAX_URL`). Then come the include and exclude URL patterns (RE2), deduplication and `max_links` (at most 500). **Any host is accepted.**
- **Worker to linked pages:** one `GET` per candidate, up to `max_items_per_run`, through the same `ctx.fetcher` with the same rate and **the same robots override**. Each page is extracted in its own child, one at a time.
- **Object store:** linked pages' raw bodies under `raw/{sid}/{sha256}` and texts under `text/{sid}/{hash}.txt` when new or changed. The listing state goes under `state/{sid}/{sha256}.json` once per run in `finish`, and the manifest goes under `raw/{sid}/runs/{run_id}.json`. `ctx.load` reads the previous state only under the exact `state/{sid}/<64 hex>.json` key.
- **Cursor (CP-16):** `{"listing_ref": key}`, written as before: no failures, not cut short, success or partial, and the source not saved during the run.
- **Manifest to M4:** each new or changed linked page with `previous_text_ref`, which is checked as this source's text key (R1).
- **Trust boundary:** the listing page, its hrefs, and every linked page and host are hostile (8.1). The cursor and the state object are treated as possibly stale or edited.

| 1 | medium | **A listing page can send the worker to any public host, and an admin's robots.txt override for the listing source is applied to those hosts too.** `discover` accepts every href that `entry_link` accepts, whatever its host (`web_page.py:151-158`). The include and exclude patterns are optional, and none is set by default. `fetch` passes `job.robots_override` for every candidate (`web_page.py:78-79`), and `CaptureFetcher` hands it to `RobotsPolicy.check` for every hop of every host (`safe_fetch/capture.py:69-70`). 8.3 makes an override an admin decision with a written reason about a source, and that reason is about the listing site, not about hosts the page links to. **Failure case** (`probe_listing.py`, L1): a listing on `regulator.example` links to `/a`, `https://elsewhere.example/x` and `https://third.example/private`, and `third.example`'s robots.txt is `Disallow: /`. With an override on the source, all three are fetched and stored (`items_new` 3). Without one, `third.example` is refused and the other two are fetched. A hostile or compromised listing can also point up to `max_links` fetches a run at a third party, with our user agent and contact address, within the per-host rate. **Fix:** (a) apply the robots override only to the host of `page_url`, and obey robots.txt on every other host (pass `robots_override=None` when the candidate's host differs); (b) by default fetch only links on the listing's host (and its redirects' checks via `allow_hop`), with off-host links allowed only through an explicit setting, such as an `allowed_hosts` list like `web_crawl`'s `allowed_domains` (a CP, as `connectors.yaml` has no such field) or a required include pattern. Test L1 both ways. | | |
| 2 | medium | **One linked page that fails, or a run cut by the deadline, discards the state of every page, so every later run reports the same pages as `new` or `changed` again.** The listing state is written only through `ctx.state`, which `run_connector` keeps only when `failures == 0 and not cut_short` (`execution.py:242`). In listing mode one run covers many independent pages, and any `ConnectorError` other than `unavailable` counts as a failure (`execution.py:207-214`): `not-html`, `http-status`, `too-slow`, `too-large` and `parse-failed`. **Failure case** (`probe_listing.py`, L2): a listing with `/a`, `/b` and `/report.pdf` (a PDF, so `not-html`) gives `partial` / `some-failed` with `/a` and `/b` both `new` on run 1, and again on runs 2 and 3. That is three manifests with the same two `new` documents, and the cursor is never written. Listings of regulatory documents often link PDFs, so this is the ordinary case, not an edge case. L6: a run cut by the deadline reports its first page `new` again on the next run, and pages after the cut are never reached. Under the old single-page design one page was one document, so all-or-nothing was right. Here it turns one bad link into a permanent duplicate stream to M4. **Fix:** in listing mode write the state whenever discovery ended normally, including after failures and a deadline cut. Each fetched page takes its new entry, and each failed or unreached page keeps its previous entry (`finish` already does this). Keep the all-or-nothing rule for connectors that resume by date. Consider treating `not-html` on a linked page as a recorded skip (`unavailable`). Test L2 and L6 over two runs, asserting `unchanged` on the second. | | |
| 3 | medium | **The run budget does not hold against a hostile listing, and BL-98 (a)'s "stop after a few `too-slow` or `too-large` pages" is not done.** Each linked page can cost a 20 s child (`isolate.WALL_SECONDS`), and its fetch can cost up to three attempts of up to 60 s per hop (`MAX_ATTEMPTS`, SafeFetcher's per-hop deadline). Up to `min(max_links, max_items_per_run)` pages run, at most 500. `check_job` estimates only `(items + 2) * 60 / rate` (`services.py:254`). **Failure case** (`probe_slow_guard.py`, S1): a listing of 30 pages that all answer `too-slow` makes the run try all 30. In production that is 600 s of children, and 500 pages are about 10,000 s, so the run ends at the 45-minute deadline every time. With finding 2, nothing is saved, and the run re-reports what it reached. Two such sources keep both worker processes of a container (`--concurrency 2`) busy continuously. **Fix:** stop extracting for the run after, say, 3 `too-slow` or `too-large` pages, ending it `partial` with a fixed reason, as BL-98 (a) asks. Count 20 s per linked page in the save-time check for listing mode, or cap `min(max_links, max_items_per_run)` so it fits. Test S1. | | |
| 4 | low | **When a listing has more links than `max_items_per_run`, the same first pages are fetched every run and the rest never are, and the first run's message says the opposite.** Candidates come in document order, and the run breaks at `max_items` (`execution.py:192`). `finish` keeps state only for what was fetched or was known. Refuse at save a `max_links` above `max_items_per_run`, or warn. Test L3. | | |

**Sign-off at review:** commit `a1582cd` is **not signed off**. The new key handling is sound:
- the state object is read only under the exact `state/{sid}/<64 hex>.json` key;
- a missing, broken or foreign state means starting afresh;
- per-page `previous_text_ref` values are checked as this source's text keys;
- links come only from the child, bounded and shape-checked.

Three medium findings remain:
- Finding 1: a listing can make the worker fetch any public host, with the listing source's robots.txt override applied to hosts nobody reviewed, against 8.3.
- Finding 2: one PDF link or one slow page discards the state of every page, so every run re-sends the same documents to M4.
- Finding 3: the run budget and BL-98 (a)'s stop rule do not hold against a hostile listing.

Findings 4 to 6 are low and can follow, but the tests for findings 1 to 3 should come with the fixes. · M3 web listing independent review · 2026-11-18

## Check of re-verification R1 and R2 (`M3-web-page-review.md`, fixed in `39de270`)
- **R1: fixed.** `_own_text_ref` passes on only `fullmatch(rf"text/{re.escape(source_id)}/[0-9a-f]{{64}}\.txt")`. A trailing newline, upper-case hex, another source, `raw/` keys, traversal, a non-string and a 100,000-character string all give `None` (`probe_slow_guard.py`, R1; the new parametrized test). The listing path uses the same check for each page's previous key (`web_page.py:182`).
- **R2: fixed for the forms in the record.** The test now walks the syntax tree of every module outside `capture/extract/` and refuses imports of `html5lib` and `regwatch.capture.extract.tree`, `.text` and `.select`, allowing only `select` in `connectors/config.py`. `web_page.py` now takes `ParseError` from `extract.isolate`. In `probe_slow_guard.py`, R2-a to R2-d (absolute from-import, alias, parenthesised package import, `html5lib`) are all caught. Two forms still pass: relative imports (`from ..extract import tree`, R2-e and R2-f), because the test reads `node.module` without `node.level`, and `importlib.import_module` (R2-g). Neither form is used anywhere in `regwatch/` today (grep), and Ruff's configuration does not ban relative imports. **Residual (info):** resolve relative imports against the module's package in the test, or enable Ruff's `TID252` (ban relative imports), and refuse `importlib` and `__import__` outside `core/`. This does not block.

## Checked and found fine
- **State key and contents:** `_own_listing_ref` requires the exact key, so an edited cursor cannot name another source's object or a non-state object. `_previous_listing` treats a missing object, `OSError` (such as a directory), `ValueError` (bad JSON or UTF-8) and a non-map as no previous state, and keeps only string URLs mapped to two strings (tested). `ctx.load` cannot see a malformed key, because the pattern is stricter than the store's.
- **Previous per page:** `hints["previous"]` is built by the connector from the state or the cursor, always two elements. `fetch` compares only the hash, and the text key goes to M4 only through `_own_text_ref`. An edited state can at most make a page look `unchanged` or `changed`; it cannot point M4 at another object.
- **Links from the child:** `links` returns at most 2,000 hrefs of at most 2,048 characters, deduplicated, in document order. `_answer` refuses any other shape or size as `parse-failed` (tested). The selector is compiled at save (`WebPageConfig._listing`) and again in the child. Listing mode without a selector is refused at save, and as `bad-config` at run time for a stale row (tested).
- **Link resolution:** `entry_link` refuses non-http(s) schemes (`javascript:`, `mailto:`, `data:`), userinfo, backslashes, controls and bidi characters, private or numeric hosts, local names and over-long URLs. It rebuilds the URL from SafeFetcher's own parse, so what is deduplicated, filtered and stored is what is fetched. Every fetch, redirects included, still goes through SafeFetcher's address checks, robots.txt (without an override) and the per-host rate.
- **URL patterns:** RE2 through `compile_pattern`, at most 20 per list and 200 characters each, checked at save. Matching is linear: at most 2,000 URLs × 40 patterns of 2 KiB.
- **`finish` and the `max_items` break:** `finish` runs inside the deadline block only after the candidate loop ends, normally or by the `max_items` break. Pages not fetched keep their previous entries, and pages no longer listed drop out (tested). It does not run when discovery raises or the deadline cuts the run, so a partial `pages` map is never saved. `ctx.state` is honoured only under the same rule as before, so `finish` cannot advance the cursor past a failure. Unchanged pages record `text/{sid}/{hash}.txt`, which an earlier run stored under the same hash.
- **Object store growth for pages:** nothing is stored for unchanged linked pages (raw or text), and state objects are content-addressed, so an unchanged listing rewrites the same key (L2: one state object after three runs).
- **Isolation:** the listing page and every linked page are extracted through `extract_isolated`, one child at a time under the per-loop lock. The dry run's `discover` extracts on the worker, not in the API.
- **Single mode:** behaviour is unchanged. `hints["previous"]` carries the cursor's hash and key, `ctx.state` is set only for a new or changed page, and the tests from the single-mode review still pass.
