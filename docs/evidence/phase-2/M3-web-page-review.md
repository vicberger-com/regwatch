## Data flows touched
- **Worker to the page's host:** one `GET page_url` per run through `ctx.fetcher` (`_CountingFetcher`, `CaptureFetcher`, `SafeFetcher`), with the job's rate and robots override; robots.txt is read by `RobotsPolicy`. Redirects are followed and checked by SafeFetcher; `final_url` is recorded.
- **Worker to the extraction child:** the first 2 MiB and one byte of the body, base64 in JSON, and the charset from the `Content-Type` header (at most 40 characters); the child answers text, `content_hash`, title, date, method and warnings.
- **Worker to the object store:** the raw body under `raw/{source_id}/{sha256(body)}` on every successful fetch; the normalized text under `text/{source_id}/{content_hash}.txt` when the page is new or changed; the run manifest under `raw/{source_id}/runs/{run_id}.json` when anything is new or changed.
- **Object store to the worker (new):** `ctx.load(text_ref)` reads the previous text, where `text_ref` comes from the job's cursor and must start with `text/{source_id}/`.
- **Cursor (CP-16):** `{"content_hash", "text_ref"}` in `capture_job.cursor`, written by `_advance_cursor` only for `success` or `partial`, only if the source was not saved since the run began and only over the cursor the run started from; cleared when `source.config` changes.
- **Manifest to M4:** each new or changed document with `text`, `change` and `metadata` (title, method, warnings, content hash, `changed_pct`, published date). Unchanged documents are counted only.
- **Errors:** `ConnectorError(reason, detail)` with fixed details (`http-status` carries the integer status); `ParseError` reasons from the child; any other exception ends the run as `internal-error` with only its type name.
- **Trust boundary:** the page's body, status, headers and redirects are hostile (8.1). The cursor is written only by the worker but is treated here as possibly stale or edited.

## Checked and found fine
- **Key confinement:** `text_ref` must start with `text/{source_id}/`, where `source_id` is the source's UUID string, and the trailing `/` stops a prefix match on a longer id. The store then requires `_KEY` (lower case, digits, `-`, `_`, `.`, at most eight segments of 128 characters), refuses `.` and `..` segments, and checks that the resolved path stays inside the root, so a symlink cannot lead out. Probe: `text/{sid}/../{other}/x.txt` is refused. The test `test_a_baseline_from_another_source_is_never_read` covers a foreign prefix. Keys written by the connector are built from `source_id` and SHA-256 hex.
- **Lost baseline:** a missing object, a foreign `text_ref` or no `load` means `previous is None`, which stores the new text, sets the state and reports `changed` (or `new` with no prior hash). It fails towards reporting (tested).
- **Identical and emptied pages:** an equal hash is `unchanged` with no state, so the cursor is kept (tested). An emptied page scores 100 % and is `changed` (P7). `changed_pct("", "")` is 0 and is reached only when the hashes differ, which cannot happen for two empty texts. Duplicate lines are counted with multiplicity (S4).
- **Threshold arithmetic:** `pct < threshold`, so a share equal to the threshold is `changed` (S3); a threshold of 0 makes every hash change `changed`; the schema bounds it to 0 to 100 and refuses NaN; a `NULL` column falls back to 5.
- **Cursor writing:** `ctx.state` is set only on `new` or `changed`, after the text is stored. `run_connector` writes it only with no failures and no deadline cut, and not when it equals the starting cursor; `_close` passes it to `_advance_cursor` only for `success` or `partial`, which skips the write if the source was saved since the run was created and otherwise updates only where the cursor still equals the one the run started from (SQL `NULL` handled). Saving a new `config` clears the cursor and fires the `updated_at` trigger, so a run of the old URL cannot write its baseline over the new one. Only one unfinished run per job exists (`uq_capture_run_unfinished`). A cursor that is not written means the next run reports the change again, which errs towards reporting.
- **Counting:** unchanged documents count towards `max_items` and towards success in `_verdict`; `items_new` counts `new` and connectors that set no `change`, so RSS and API feed counts are unchanged; the manifest is written only when something is new or changed (tested). The columns exist in the model and the schema.
- **HTML only:** `FetchResult.mime` is the lower-cased type before `;`, so `TEXT/HTML` and `text/html ;charset=...` are accepted, and a missing or other type (`text/plain`, `application/pdf`) is `not-html` before anything is stored (tested for PDF; P9). No sniffing is done, which is the safe choice.
- **Charset:** `_charset` takes the `charset` parameter case-insensitively, strips quotes and caps it at 40 characters. html5lib ignores unknown labels (`iso-2022-kr` gave normal text) and the `UnicodeError` fallback handles labels that are not text. A `utf-16` label on an ASCII body gives the same garbage a browser would; changes are still detected. Unpaired surrogates, whether as `&#xD800;` or as raw UTF-16 bytes, become U+FFFD, so `text.encode()` in `_compare` cannot fail (P8, `probe_surrogate.py`).
- **Errors:** `http-status` carries only the integer status; `not-html`, `not-implemented` and the `ParseError` detail are constants; the `ParseError` reason is one of the child's fixed codes. Unexpected exceptions record only their type name; the key text of an `ObjectStoreError` goes to the log, not to the run.
- **robots.txt and rate:** the page fetch passes `rate_per_minute` and `robots_override` exactly as the RSS connector does; a robots or rate refusal is a skip handled by `run_connector`, and the connector stores nothing before the fetch succeeds.
- **Isolation and budget:** the only parse path is `extract_isolated`, with the body cut to 2 MiB and one byte; one child per run in single mode; `ParseError` is not retried by `_retrying` (only `timeout` and `connect` fetch refusals are); the run is well inside `RUN_DEADLINE_S`. `discover` raises `not-implemented` for `listing` and `render_js` before any fetch (tested).
- **Dry run:** `preview` runs `discover` only, with a store that refuses writes and no `load`, so a dry run neither fetches the page nor reads or writes texts.
