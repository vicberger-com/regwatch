# Development stack

```
make dev     # creates deploy/.env on first run, builds the api image, starts the stack
make stop
```

- `http://localhost/` serves the SPA; `http://localhost/api/v1/health` and `/api/v1/version` go through `proxy` (Caddy) to `api`; every other path goes to the Vite dev server (`web`).
- Mailpit UI: `http://localhost:8025` (bound to 127.0.0.1).
- Optional sidecars: `docker compose -f deploy/compose.yaml --profile search --profile translate up`.
- `deploy/.env` is generated by `scripts/dev-env.sh` from `docs/contracts/env.example` with a random secret key and database password. It is git-ignored; `scripts/dev-env.sh --force` recreates it (the database volume keeps the old password, so also run `docker volume rm regwatch_pgdata`).
- Only `proxy` publishes ports (80, 443) and `mailpit` publishes 8025. All other services sit on the internal `regwatch` network, which has no route to the internet.

## Building behind a TLS-intercepting proxy

The api image build downloads packages from PyPI. If your network re-signs TLS with its own CA, give the build that CA as the optional `build_ca` secret, for example:

```
docker build --target dev --secret id=build_ca,src=/path/to/ca.pem -t regwatch-api:dev api
docker compose -f deploy/compose.yaml up
```

Without the secret the build uses the image's public trust store.
