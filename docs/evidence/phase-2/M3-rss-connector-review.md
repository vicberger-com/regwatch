## Data flows touched
- **Worker to the feed's host:** `discover` fetches `feed_url` through `ctx.fetcher` (CaptureFetcher, then SafeFetcher). `fetch` fetches each candidate link when `fetch_full_page` is on.
- **Feed bytes to feedparser:** the strict parser is expat through `xml.sax`. On any SAX error it falls back to the loose sgmllib parser.
- **Feed to candidates:** `url`, `title`, `summary`, `external_id`, `language` and `published_at` go to M4 next, then to users' browsers, emails and exports.
- **Worker to the object store:** `raw/{source_id}/{sha256}` holds the fetched page. With `fetch_full_page` off, `raw/{source_id}/{sha256}.txt` holds the summary text.
- **Errors:** `ConnectorError(reason, detail)` maps to `capture_run.error_class` and `error_message`, which `sources.read` holders can see.
- **Trust boundary:** everything in the feed body and its response headers (the feed site, or anyone who can change what it serves, is hostile, 8.1).

## Findings
| # | Severity | Description | Fix PR | Verified |
| --- | --- | --- | --- | --- |
| 1 | high | **feedparser opens the feed body as a local file path.** `_parse` (`rss.py:88-92`) refuses `str` but passes `bytes` to `feedparser.parse`. `_open_resource` (`feedparser/api.py:117-127`) first calls `open(url_file_stream_or_string, 'rb')` on **any** non-stream input, `bytes` included, and parses the file if that succeeds. Every feed goes through this `open` call (seen in `poc_audit.py` for all 8 inputs); a normal feed only fails it by chance (no such path, or a name too long). **Failure cases:** (a) a feed server answers `/dev/zero` (9 bytes): `open().read()` grows without limit and the worker dies of `MemoryError`, or the OOM killer takes it (`poc_zero.py`). (b) It answers `/tmp/m3rss-review/localfeed2.xml`: `discover` yields that local file's entries as candidates, with title `FROM-LOCAL-DISK` (`test_poc_rss.py::test_poc_feed_body_is_opened_as_local_path`). (c) The parse result tells whether a path exists (an existence oracle on the worker). The module docstring (`rss.py:7-8`) and `test_feedparser_never_gets_a_string` (`test_connector_rss.py:179-182`) claim the opposite. **Fix:** `feedparser.parse(io.BytesIO(body), ...)`. `_open_resource` returns `.read()` at once for a stream, and `fixcheck.py` confirms that the path is not opened. Add a test that a body naming an existing local feed file yields `malformed-feed`. | | |
| 2 | high | **Entity amplification through the loose-parser fallback.** feedparser's `replace_doctype` keeps "safe" entities, those whose value contains no `&`, when they start a line (`sanitizer.py:891-949`). Expat stops when the amplification limit is breached, but feedparser then reruns the **loose** parser with the same entity table (`api.py:268-272`, `mixin.py:368-369`), which expands every reference with no limit. **Failure cases** (`gen.py flat`, `flat_broken`): a 100 KB feed with one 100,000-character entity used 1,000 times took 7 s at 1.1 GB peak RSS. A 1 MB feed (a 1 MB entity used 300 times) took 23 s at 3.3 GB. A 1 MB feed with 1,000 references was killed past 8 GB. A 10 MB body allows terabytes. The well-formed version behaves the same: expat reports "limit on input amplification factor ... breached", then the loose pass expands anyway. Scheduler finding 10 lets a run that kills its worker be handed over up to three more times. The docstring claim (`rss.py:9-11`: "a feed that only parses that way yields nothing") is false. `test_entity_expansion_bombs_end_quickly` passes only because its nested entities contain `&` and feedparser drops them (finding 9). **Fix:** before parsing, refuse any body whose prolog has a DOCTYPE internal subset or any `<!ENTITY` (`malformed-feed`). Real RSS and Atom do not need one, and the Netscape RSS 0.91 DOCTYPE has no internal subset. The expat pre-pass in `precheck.py` refuses these in under 1 ms. Also cut each text value before `plain_text` (for example to `4 * limit`), so `nh3` and `html.unescape` never see megabytes. Add the `flat` and `flat_broken` cases as tests with a memory or time bound. | | |
| 3 | medium | **Parsing within the 10 MB cap costs minutes and gigabytes, on the event loop, with no limit.** `_parse` runs synchronously inside `async discover` (`rss.py:111`). The worker has no Celery `time_limit`, no `worker_max_memory_per_child` and no rlimit (`core/worker.py`, `core/entrypoints.py:24`). **Measured on 10 MB-class bodies** (`harness.py`): 9 MB of unclosed `<a>` tags (loose path) took 77 s at 2.4 GB; 1,000,000 nested elements (strict path) took 22 s; 160,000 well-formed items took 12 s, and 28 s when one broken tag forces the loose path. Huge attributes were fine (0.08 s). **Fix:** (a) an expat pre-pass with a depth cap of about 64 and the DTD refusal from finding 2 (`precheck.py`: 0.001 s on the deep and tag-soup bodies, 0.16 s on 10 MB of items); (b) a feed-specific body cap through `SafeFetcher.with_limits` (2 MB is ample for news feeds), and loose parsing only below about 1 MB; (c) parse with `anyio.to_thread` or in a child process with `RLIMIT_AS` and a wall-clock limit; (d) a Celery `task_time_limit` and `worker_max_memory_per_child` for `capture.run_job`. | | |
| 4 | medium | **"No markup survives" is false: double-encoded markup comes out as literal tags.** `plain_text` (`rss.py:55`) runs `nh3.clean` and then one `html.unescape`. nh3 escapes text, so a feed that encodes markup one level deeper than feedparser decodes ends up with real angle brackets. **Failure case** (`test_poc_rss.py::test_poc_double_decode`): `<title>&amp;lt;img src=x onerror=alert(1)&amp;gt;</title>` gives the candidate title `<img src=x onerror=alert(1)>`, and `<description>&amp;lt;script&amp;gt;...` gives the summary `<script>alert(1)</script>`. With `fetch_full_page` off, that summary is the stored `text/plain` body and `RawDocument.text` (`rss.py:139-143`). The M3 test plan says script in extracted content "must be stripped before storage". The docstring (`rss.py:15-17`) and the ASSUMPTIONS row say no markup survives, and `test_plain_text` pins `&amp;lt;` to `&lt;` as if that were fine. React and Jinja autoescape make this safe only while every later stage escapes, including emails, PDF and CSV, as 8.1 requires. The connector should not advertise an invariant it does not keep. **Fix:** repeat `nh3.clean(tags=set())` plus `unescape` until the text stops changing (at most 3 rounds), so markup revealed by decoding is stripped too. Otherwise, document that candidate text is plain text that may contain `<` and must always be escaped, correct the ASSUMPTIONS row, and test both cases. | | |
| 5 | medium | **Candidate links are checked less strictly than SafeFetcher's `parse_target`, and with `fetch_full_page` off they are never checked.** `entry_link` (`rss.py:60-74`) only requires an http or https scheme, a host, printable characters and 2,048 characters at most. **Failure cases** (`test_poc_rss.py::test_poc_links_kept`, all kept as candidate URLs): (a) `https://user:pw@example.org/a` has userinfo. (b) `https://evil.example\@example.org/a` is a parser differential: Python's `urlsplit` reads host `example.org`, while WHATWG browsers treat `\` as `/` and go to `evil.example`. Any later host check (`include_url_patterns`, a host shown next to the link) would believe the wrong host. (c) `https://exаmple.org/a` (Cyrillic `а`) is stored unnormalised, a homograph. (d) `http://169.254.169.254/latest/meta-data/` and `http://127.0.0.1:8000/api/admin` are private IP literals. (e) `xml:base="http://10.0.0.5/"` with a relative `href` resolves to a private URL (`test_poc_xml_base_private`). With `fetch_full_page` on, SafeFetcher refuses (a), (b) and (d), so nothing is fetched. With it off, `fetch` (`rss.py:138-143`) makes a `RawDocument` for the private URL without any check (`test_poc_fetch_full_page_off_never_checks_url`), and M4 and the UI receive it as an item's source link. **Fix:** in `entry_link`, call `parse_target` (it refuses userinfo, controls and invalid IDNA), refuse `\`, and rebuild the URL from the `Target` so the host is stored as an A-label. Refuse IP-literal hosts that `check_address` rejects. Consider dropping links whose host differs from the feed's registrable domain unless the job allows it. Test each case. | | |
| 6 | low | **Exceptions other than `ConnectorError` can escape `discover`, with text from the feed.** `ConnectorError` itself is fine: its details are constants or an integer status (`rss.py:110,113,118`). But `Content-Type: application/rss+xml; charset=punycode` makes feedparser raise `UnicodeError: Invalid extended code point '<'` out of `discover` (`poc_charset.py`). `fetch` lets `FetchRefusedError` through, whose detail names the candidate's host, which comes from the feed (`policy.py:141`, "`{host}` could not be resolved: `{exc}`"). **Fix:** wrap `_parse` in `except Exception` and raise `ConnectorError("malformed-feed", constant)`. When the executor is wired, map `FetchRefusedError` by its `reason` only and never store `str(exc)` (BL-90 (h)). | | |
| 7 | low | **`language` and `external_id` are only trimmed text.** `language` is any printable text up to 35 characters (`rss.py:114,131`). `x" onmouseover="a(1)` is kept (`test_poc_language_free_text`), which is dangerous wherever it reaches a `lang` attribute unescaped. `external_id` goes through the HTML sanitiser and unescaping, which change ids, and is cut at 500 characters, so two long ids sharing a prefix collide for de-duplication. feedparser also resolves a `guid` with the default `isPermaLink` against the feed URL (`<guid>&lt;b&gt;id&lt;/b&gt;</guid>` became `https://example.org/feeds/id`). **Fix:** accept `language` only if it matches a BCP 47 shape (`[A-Za-z]{2,3}(-[A-Za-z0-9]{1,8})*`), else `None`. Keep `external_id` as given, with controls removed, and drop it (rather than cut it) when it is over the limit, or store a hash of it. | | |
| 8 | low | **`max_entries` has no minimum.** `RssConfig.max_entries` (`connectors/config.py:37`) and `connectors.yaml` set only `maximum: 1000`. A value of `-1` makes `feed.entries[:min(-1, 200)]` (`rss.py:116`) drop the last entry, and `-1000` drops everything. **Fix:** `ge=1` in the model and `minimum: 1` in the contract (the contract test keeps them equal). | | |
| 9 | low | **Several tests do not prove what they claim.** (a) `test_entity_expansion_bombs_end_quickly` (`test_connector_rss.py:131-143`): every nested entity contains `&`, so feedparser removes it before expat sees it (the title comes out as the literal `&a9;`). Expat's limit is never involved, and finding 2 passes. (b) `test_external_entities_are_not_loaded` asserts on `site.paths`, but a fetch by feedparser itself would use urllib and never reach the mock transport, so the assertion cannot fail for that reason. The audit-hook probe (`poc_audit.py`) is what shows that no socket is opened. (c) `test_feedparser_never_gets_a_string` misses the `bytes` path (finding 1). (d) Nothing covers the loose fallback's cost, userinfo, backslash, IDN, private-literal links, or double-encoded markup. (e) BL-89's deterministic test (`test_taxonomy.py:515-541`) relies on `asyncio.sleep(0.3)` and `sleep(0.5)`. If the merge request had not yet read its terms after 0.5 s, it would read them after the holder commits, and the pre-lock checks would give the same 404 or 422 on the old code. **Fix:** add the PoCs above as tests. In the BL-89 test, poll `pg_stat_activity` until a backend shows `wait_event_type = 'Lock'` before setting `release`. | | |
| 10 | info | (a) With `fetch_full_page` off, the stored "raw" body is the sanitised summary cut to 5,000 characters, not the entry as captured. `content` (for example `content:encoded`, often the full text) is ignored, and the feed body itself is never stored, so there is no provenance for what the feed said. (b) `fetch` stores the bodies of non-2xx answers under `raw/` too. (c) `raw/` objects are hostile HTML with no content type set by `ctx.store`; they must never be served inline to a browser. ## Checked and found fine
- **feedparser and the network:** with the audit hook armed, no `socket.*` or `urllib.Request` event fired for these inputs: `<!DOCTYPE rss SYSTEM "http://10.9.9.9/...">`, an external parameter entity, `SYSTEM "file:///etc/passwd"` (strict and loose paths), `<?xml-stylesheet href="http://10.9.9.9/...">`, XInclude, or `xml:base="file:///etc/"`. feedparser drops `SYSTEM` entities in `replace_doctype` and sets `feature_external_ges` to 0. The XInclude element is ignored. The only `open` events were the path open of finding 1. A `file://` link built from `xml:base` is dropped by the scheme check.
- **XXE:** external entities are never resolved. The title keeps the literal `&f;`.
- **Controls and bidi:** `isprintable` removes C0 and C1 controls, U+202E and the other `Cf` format characters, U+2028 and U+2029, and NBSP. Runs of white space collapse to one space. Combining marks survive but stay within the length cap (`test_poc_zalgo_and_length`: 1,000 characters).
- **Hostile `charset`:** `zlib`, `base64`, `rot13`, `uu` and `hex` are refused by `bytes.decode` as not text encodings, and feedparser falls back to UTF-8; no decompression happens. `utf-7`, `idna` and `unicode_escape` decode, and the markup stripping still applies. `punycode` raises (finding 6).
- **Storage keys:** `source_id` comes from the job row, not the feed, and the rest is a SHA-256 hex digest, so the feed cannot cause traversal or a collision. The `.txt` suffix keeps summary objects apart from page objects. Equal bodies share an object, as the ASSUMPTIONS row says.
- **`ConnectorError`:** its details are constants or an integer status and never quote content.
- **Page fetches:** `fetch` with `fetch_full_page` on goes through `ctx.fetcher`, so SafeFetcher checks every hop. Only `content-type`, `last-modified` and `etag` headers are kept.
- **BL-89 (`ff85b1d`):** the fix is correct.
  - `_reload` re-selects the row with `populate_existing` after the row locks, so under READ COMMITTED it sees what was committed while the request waited. A deleted row gives 404 instead of the `InvalidRequestError` 500.
  - The new check on `target.active` after the lock closes a real hole: on the old code a merge into a target deactivated during the wait went ahead. `check_parent` now runs on the fresh rows too.
  - `update_term` cannot move a term to another facet, and a concurrent `UPDATE` of `active` waits on the merge's `FOR UPDATE`, so it can only happen before the reload (seen) or after the commit (ordered after).
  - Nothing new is opened: an inactive source can still be merged, as before.
  - Run against the old code (`old/`), both parametrised cases of the new test fail: `InvalidRequestError` for the delete case and a non-422 answer for the deactivate case. On the new code they pass, as does the relaxed concurrent test (204 for the delete, 200 or 404 for the merge, 3 tags kept). The caveat about sleep-based timing is finding 9 (e).
- **`f8e154f`:** adding 413 to the expected statuses of the negative-data check is correct. A body over the 2 MB cap is a valid rejection of invalid data. `positive_data_acceptance` is unchanged, so a 413 on valid data would still fail.
- **License evidence (`0d3c0a3`):**
  - Over the GitHub API, the annotated tag `v6.0.14` of `kurtmckee/feedparser` dereferences to commit `14425f6851790184fbf7bbd8076de237d5f444f9`. The annotated tag `v2.1.0` of `python-syndication/feedparser-sgmllib` dereferences to `36924f1700d36901b31c4db30d91f0b55ee82ad2`. Both match C17 and C18.
  - feedparser's `LICENSE` is BSD-2-Clause for the code and tests (no advertising clause). Its `docs/` directory has a 2-clause documentation licence of its own and is not in the wheel (`RECORD` has no `docs/`), as C17 says.
  - feedparser-sgmllib's `LICENSE` is the full Python licence stack (history, PSF-2.0, BeOpen, CNRI 1.6.1, CWI), which is SPDX `Python-2.0`, as C18 says, and allowed under BL-59. Its wheel metadata declares `License-Expression: PSF-2.0`; PSF-2.0 is allowed too (BL-53).
  - Both texts are byte-identical to the `LICENSE` files in the installed wheels.
