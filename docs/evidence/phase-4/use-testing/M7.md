# Use testing script: M7 Report builder and stock reports

**Tester:** use-testing session, not involved in building M7 (scripted Playwright journeys, headless Chromium from the official Playwright 1.65.1 image pinned by digest `sha256:1507cbfc550a…5579`, driving the repository's own `@playwright/test` 1.65.1 mounted read-only) · **Build:** 0.1.0, the isolated QA stack at http://localhost:8180. The branch under test is `feat/M7-reports` at `46db174`; the stack's checkout is at `9cfcac0`, and the two differ only in `BACKLOG.md` and the M8 module record. Run on 2026-11-21 from 00:30 to 00:44 UTC. · **Viewport:** 1440 x 900 · **Input method:** mouse (scripted pointer, drag and typing), except M7-05, which is keyboard only · **Round:** 2

Scripts: `/tmp/ut2/m7a.js`, `m7b.js`, `m7c.js`, `m7prev.js`, `kbd.js`, `kbd2.js`, `kbd3.js` and `days.js` (outside the repository and not committed). The admin password was read only inside the scripts. Sign-in went through the API, so no screenshot shows the sign-in form. Throwaway users (two analysts, one editor) were created through the admin API. Their passwords existed only in the scripts' memory, and the users were disabled at the end. Screenshots are in `shots/`. Times are the script's wall-clock time and include fixed waits of 0.25 to 1.5 s after each action.

**Data:** the QA stack holds four items: two for Germany (DE) and two for the European Union (EU), all changed on 2026-11-20. It also holds 22 layouts named "New report" that earlier end-to-end runs left behind. No saved view existed, and no screen can create one (see U-M7-3). The precondition view "Europe 30 days" (jurisdictions EU and DE, 30 days, private) was therefore created with `POST /views`. That is the only API step in a UI journey, and the rows say where it happened.

## Proposed issues (`type:usability`)

| # | Title | Severity | Journeys | Detail |
| --- | --- | --- | --- | --- |
| U-M7-1 | Stock reports with a required parameter cannot be produced from any screen | blocker | M7-03, M7-S3 | "Jurisdiction profile" (and "Topic overview", whose topics are also required) fails with "jurisdiction: Jurisdiction is needed". `NewOutput.tsx` sends `source.report_template_key` with no `params`, although `OutputRequest.params` exists. `BuilderPage.tsx` previews with no body, so an instantiated template cannot be previewed either. Add parameter fields from `GET /reports/templates` (`parameters[]`: a jurisdiction picker, days covered, topics) to New output and to the builder preview, and offer "Print jurisdiction profile" from the Germany panel (screens.md `/`, `/jurisdictions/:code`). M7 acceptance 3 is met by the API only. |
| U-M7-2 | `/reports` lacks the stock reports, preview pane and Print, Email and Download PDF from screens.md | major | M7-06, M7-03 | The page is a single table of layouts. Add the stock report cards (thumbnails are null), a preview pane, and the commands, which today exist only on `/outputs`. |
| U-M7-3 | No screen can create or share a saved view, yet report data and sharing depend on one | major | M7-01, M7-02, S1 (M8) | The builder's "Data: saved view" list is empty for every new user. A shared layout needs a shared view, so the refusal message points to something no screen can do. Either ship the saved-view picker (open in M6) or let the builder set jurisdictions, period and facets directly. |
| U-M7-4 | The admin's list calls other users' private layouts "Shared" | minor | M7-02 | `ReportsPage.tsx` shows "Shared" for every layout that is not mine. Show the owner's name, and "Private" or "Shared" from `l.shared`. |
