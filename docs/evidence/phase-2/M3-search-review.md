## Data flows touched
- **Worker to `search`:** `InternalClient.get_json("/search", params)` sends `GET http://search:8080/search?q=...&format=json&safesearch=0&language=...&time_range=...&pageno=N` on the internal `regwatch` network. The base comes from `REGWATCH_SEARCH_URL` (a setting, default `http://search:8080`). The path is a constant in code. `q` is the source's query plus `(site:a OR site:b)`. The requests are paced through the Valkey key `regwatch:rate:internal:search`.
- **`search` to the internet:** SearXNG queries DuckDuckGo, Brave, Google and Qwant over the `egress` bridge network, which no other service joins.
- **SearXNG JSON to candidates:** `results[].url` goes through `entry_link`. `title` and `content` go through `plain_text`, then into the candidate title and `metadata.snippet`. `engines` and `unresponsive_engines` are used only for the usability check and the error message (names checked by `_ENGINE`). All of it reaches the run manifest, M4, the dry-run answer and users' browsers.
- **Worker to result sites:** `fetch_document` fetches each result through `CaptureFetcher` and `SafeFetcher` with `robots_override=None`. HTML is read in the isolated extraction child. The body is stored under `raw/{source_id}/{sha256}`, with `metadata.credibility` `official` or `secondary`.
- **Database to context:** the `search.internet` flag, the `search.provider` setting, and the URL and top-level config URLs of every enabled source whose credibility is `official` (`official_hosts`).
- **Secrets:** `SEARXNG_SECRET` is generated into `deploy/search.env` (mode 600, git-ignored) and read only by the `search` container.
- **Errors:** an `InternalError` has a fixed reason and fixed text, and becomes a `ConnectorError`. The engine names are checked. Any other exception becomes `internal-error` with its type name only.
- **Trust boundary:** SearXNG's answer is treated as compromised, as are the result pages, their redirects and robots.txt (8.1).

## Checked and found fine
- **Network exposure:**
  - `search` publishes no port and has no `ports` or `expose` entry.
  - `regwatch` stays `internal: true`. `egress` is joined by `search` alone (tested, and confirmed in the compose file).
  - `api`, `worker`, `beat`, `db`, `queue`, `pdf` and `translate` have no network other than `regwatch`. The published ports are unchanged: `127.0.0.1:80`, `127.0.0.1:443` and `127.0.0.1:8025`, all loopback.
  - The image is pinned by digest under the `search` profile, which is off by default.
- **Settings:**
  - `settings.yml` is mounted read-only and has no secret.
  - `keep_only` leaves exactly DuckDuckGo, Brave, Google and Qwant, so a bang in the query cannot reach another engine.
  - `public_instance: false`, `image_proxy: false` and `enable_metrics: false` are set. `limiter: false` is right for a service reached only by our workers, and bot detection would block them.
  - Autocomplete and the favicon resolver are left at their defaults (off), and no plugin that fetches (the Tor check) is enabled.
  - The request parameters are fixed in code, so `enabled_plugins`, `engines` or `preferences` cannot be passed.
  - An external bang (`!!`) answers with a redirect, which the client refuses as `sidecar-status`.
- **Secret handling:**
  - `SEARXNG_SECRET` is 32 random bytes as hex (tested: 64 characters, in no other env file, mode 600).
  - `deploy/search.env` is git-ignored and does not exist in the repository, and nothing copies it into an image.
  - The upgrade path writes only `search.env` and leaves the other files unchanged (tested). `--force` regenerates all four.
- **Internal client** (`probe_internal.py`):
  - `q` containing `&format=html` is encoded (`q=x%26format%3Dhtml`), so parameters cannot be injected.
  - The paths `http://evil/`, `//evil/x`, `/a/../b`, `/search?x`, `/search#`, `@evil` and `/%2e%2e/` are all refused before any request.
  - A 302 to the metadata address is `sidecar-status`, not followed.
  - A 500 with text gives only "the sidecar answered HTTP 500".
  - A 5 MB identity answer is `sidecar-too-large`.
  - 200,000 nested brackets, a 5,000-digit integer and bad UTF-8 are `sidecar-malformed`. `NaN` parses harmlessly.
  - `trust_env=False` ignores proxy variables and `.netrc`. The base URL is a typed setting from the environment, never from a source, a page or the database.
- **Hostile result URLs** (`probe_connector.py`, hosts):
  - `ftp:`, `data:`, userinfo, a backslash, `127.0.0.1`, `0x7f.1`, `localhost` and `.internal` are dropped by `entry_link`.
  - An upper-case host with a trailing dot is normalised and de-duplicated.
  - IDN hosts are IDNA-encoded. IPv6 literals are kept only when public, and are never `official`.
  - Fragments are dropped, and query strings are kept.
  - Non-dict results are skipped, and a page of only those fails `search-unavailable`.
  - Titles and snippets are plain text of bounded length.
  - Engine names in the message must match `[a-z0-9 _-]{1,40}`, at most 20 of them, and the free-text reasons are dropped (tested).
- **Huge or repeated answers:** an answer is at most 4 MB of JSON (but see finding 1). There are at most 5 pages, each paced, with repeats dropped by `seen`. At most `max_results` candidates are taken, and the run's `max_items` still applies.
- **Pacing in normal operation:**
  - Every page takes a slot on one Valkey key, `regwatch:rate:internal:search`, through the existing atomic Lua script on Valkey's clock. So queries from every worker are at least 60 s apart, with 0 to 30 s of extra spacing.
  - A query lasts at most SearXNG's 10 s plus the client's timeouts, so two never overlap.
  - No fetched host can collide with the key, because hosts never contain `:` except IPv6 literals, which `internal:search` is not.
  - With Valkey down, `take` raises the client's error, which ends the run as `internal-error` (or the dry run as "the test failed on the worker"), and no query is sent. It fails closed.
- **Robots and overrides:**
  - `robots_policy: override` is refused at save for `search_query` (tested).
  - `job_settings` drops a saved override for this kind (tested with a row saved before), and `fetch_document` always passes `robots_override=None`.
  - Every hop of every result fetch goes through `CaptureFetcher`'s robots.txt and rate checks.
  - The refactor of `ManualConnector.fetch` into `fetch_document` keeps its behaviour (`{"manual": True}` metadata; the manual tests pass).
- **Flag and provider:** the client is built only when `search.internet` is on and `search.provider` is `searxng` (tested through the database). Otherwise the run fails `search-disabled` before any request.
