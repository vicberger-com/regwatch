# Use testing script: M6 Application shell and world map UI

**Tester:** use-testing session, not involved in building M6 (scripted Playwright journeys, headless Chromium from the official Playwright 1.65.1 image pinned by digest, SwiftShader WebGL) · **Build:** 0.1.0, the isolated QA stack at http://localhost:8180. The repository checkout is `feat/M9-preferences` at `708e99b`; the stack does not report its own commit. Run on 2026-11-20 from 01:15 to 01:37 UTC. · **Viewport:** 1440 x 900 unless a row says otherwise · **Input method:** mouse (scripted pointer and typing), except M6-03, which is keyboard only · **Round:** 1

Scripts: `/tmp/ut/m6.js`, `m6b.js` and `days.js` (outside the repository and not committed). The admin password was read only inside the scripts, and no screenshot shows the sign-in form. Screenshots are in `shots/`. Times are the script's wall-clock time and include fixed waits of 0.3 to 1.5 s after each action, so a person would see the screens change faster.

**Environment note:** the QA stack is served by the Vite development server. `index.html` loads `/@vite/client` and `/src/main.tsx`, and every page logs a CSP error for the HMR websocket `ws://localhost/?token=…` (connect-src 'self'). Timings here are therefore not the production budget (M6 test plan: Lighthouse).

**Diagnostic CSS:** as shipped, the map canvas is not visible (M6-01a, finding U-M6-1). To still judge shading, hover, click and hatching, some rows were re-run with one injected rule, `.maplibregl-map{position:absolute!important}`. Those rows say "diagnostic", and so do their screenshot names (`*-diagnostic-*`, `m6-04-diag-*`). Every other row uses the app unmodified.

## Proposed issues (`type:usability`)

| # | Title | Severity | Journeys | Detail |

| U-M6-1 | The map is not drawn: its container has zero height | blocker | M6-01a, M6-S1 | `maplibre-gl.css` sets `.maplibregl-map { position: relative }`. It is loaded with the lazy map chunk, after `index.css`, so it overrides `absolute inset-0` on the engine's container (computed position `relative`, `clientHeight 0`). This was seen on the dev server; it is probably the same in a production build, where the chunk's CSS also arrives later, but that is not verified. A fix could give the container its own height or a more specific selector. Add an e2e check that the canvas height matches the region. |
| U-M6-2 | First load can leave every jurisdiction neutral | major | M6-01b | When `/map/activity` answers before the lazy engine import resolves, `engine.current?.setSteps(steps)` is a no-op, and the steps never reach the engine until they change (a period switch). Two out of two fresh browsers showed this. Pass the current steps in when the engine is created. |
| U-M6-3 | Search ignores item content and partial words | major | M6-06, M6-S2 | Only title words match. GDPR, BSI, Meldung and Sicherheitsvorfällen (all in the content) give 0, and so does "nis" for NIS2. Search the sanitized content, and the translated text when present. Consider prefix matching. |
