## Data flows touched
- **Capture worker to broker:** after a run with documents is closed and committed, `execute()` calls `processing.tasks.enqueue(manifest_key)`, which is `send_task("process.extract", [key], queue="process")`. A failure is logged with `_log.exception` and not retried.
- **Broker to process worker:** `process.extract(raw_document_ref)` calls `process_manifest`. The key must fully match `raw/{uuid}/runs/{uuid}.json`, and the source and run ids come from the key. The worker runs both queues at concurrency 2, with a soft limit of 3,300 s and a hard limit of 3,600 s, `acks_late` and `task_reject_on_worker_lost=False`.
- **Object store to M4:** the manifest JSON is read under that key. Each row's `url`, `text`, `title`, `summary`, `language`, `published_at`, `external_id`, `body_ref` and `metadata` are read. `final_url`, `mime`, `status`, `change` and `fetched_at` are not read.
- **M4 to PostgreSQL:** each row is handled in its own transaction:
  - `item` is found by global `url_hash` with `FOR UPDATE`, or created;
  - `item_version` holds `content_text` (up to 1,000,000 characters) and `diff_from_previous` (up to 64 KB);
  - `item_jurisdiction` rows other than `user` are deleted and re-inserted;
  - `change_event` gets one row per jurisdiction, with `severity` and a `summary` built from the title.
- **Downstream:** titles, summaries, diffs, tags and events go to the UI, the map (REQ-06), notifications and exports in later modules.
- **Logs:** `processing_row_failed` records `run_id` and the exception's type name. `processing_handover_failed` records `run_id` and a traceback.
- **Trust boundary:** every manifest field is hostile (8.1). The page or feed controls it, and the manifest itself is only as trustworthy as the connector and the object store.

## Checked and found fine
- **Manifest key:** `MANIFEST.fullmatch` allows only `raw/<36 hex-or-dash>/runs/<36 hex-or-dash>.json`. `uuid.UUID` then rejects malformed ids, so a key can name no other prefix, no `..` and no absolute path (tested with `raw/../../etc/passwd`). The source and run come from the key, not the manifest body, and a run id unknown to the database stores `run_id` NULL.
- **Manifest shape:** a missing or empty object gives no rows. A non-list `documents`, or a non-dict row, is counted and skipped. At most `MAX_ROWS` (2,000, equal to the save-time cap on `max_items_per_run`) rows are read. Malformed JSON fails the task before any write.
- **Row isolation:** the prologue reads commit before the loop. Each row's ingest, geotag, tags and events commit together or roll back together. A failure of one row did not affect the others (P3: 8 stored, 4 failed).
- **Lengths:** title 500 and summary 4,000 through `plain_text` (cut before cleaning, controls removed), `external_id` 500, `language` 35, text 1,000,000, diff 64 KB measured in UTF-8 bytes with a marker. URLs are at most 2,048 characters through `parse_target`, and a 2,040-character URL is stored (P3). `canonical_url` has no b-tree index, so long values cannot overflow one.
- **Canonical URL:** `parse_target` refuses control characters, spaces, userinfo and schemes other than http and https. The host is IDNA-encoded and lower-cased, the default port is dropped, the fragment is dropped, and the query is kept. `javascript:` gives `skipped` (tested).
- **Idempotency:** the same content for a known URL is `unchanged` with no version and no event, and the same manifest twice gives no new version (tested; P5's first replay).
- **User-assigned jurisdictions:** `tag_jurisdictions` deletes only `assigned_by != 'user'`, reads the surviving user rows, and skips hits for them. In P6, FR (turned into a user row) and DE (added by a user) survived a reprocess that detected ES.
- **INTL fallback:** `INTL` is seeded (`seed/jurisdictions.yaml:262`), and an item with no jurisdiction gets one event under it (tested).
- **Geotag patterns:** every cue is `re.escape`d and wrapped in fixed look-arounds, with no quantifiers. There are 1,279 patterns, compiled once from shipped data and never from content. The worst inputs I tried ("a" or "." repeated, 400 words of cues) take 30 to 60 ms. `evidence` holds only the kind and the cue. The gazetteer build checks pinned SHA-256s and keeps no names under 4 Latin characters.
- **Diff:** `unified_diff` uses line `SequenceMatcher` only (no intraline pass) on at most 5,000 lines. A 1,000,000-character single line, 5,000 different lines and repeated lines each take under 10 ms.
- **Summaries:** an event summary is the cleaned title plus a number, at most 500 characters. No text, URL or diff goes into it.
- **Logging:** `processing_row_failed` holds only `run_id` and the exception type, so no content and no SQL parameters are logged. The task logs its key only. The hand-over traceback is a broker connection error.
- **Translation flag:** `translation_pending` is set for any language not starting with `en`. This never blocks the pipeline (Q5).
- **Worker:** `process.*` is routed to `process`, messages are JSON only, remote control is off, and the address-space and memory-per-child caps apply to processing as well.

**Sign-off at review:** commits `f1070ec` and `d40ee8c` are **not signed off**.
