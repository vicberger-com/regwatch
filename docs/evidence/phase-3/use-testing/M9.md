The repository checkout is `feat/M9-preferences` at `708e99b`. Run on 2026-11-20 from 01:33 to 01:37 UTC. · **Viewport:** 1440 x 900 unless a row says otherwise; browser colour scheme light · **Input method:** mouse (scripted), except M9-S3, which is keyboard only after setup · **Round:** 1

Scripts: `/tmp/ut/m9.js`, `m9b.js` and `days.js` (outside the repository and not committed). The password was read only inside the scripts; sign-in forms were never captured. Screenshots are in `shots/`. "Device 2" and "device 3" are fresh browser contexts, with empty storage, signed in as the same admin.

Data changed: only the admin's own preferences and sessions. One extra session, made by the script with the user agent "ut-m9-04 second device", was created and signed out from the list in M9-04. One older stale session of the admin, left by earlier test runs, was also signed out by a keyboard misstep in the first try of M9-S3. At the end, the preferences were restored with `PATCH /me/preferences` to: theme system, font_scale 100, density default, accessibility_preset false, reduced_motion system, toolbar_labels hover, timezone UTC, idle timeout 480, remember_me_default false. The server confirmed them (HTTP 200).

## Proposed issues (`type:usability`)

| # | Title | Severity | Journeys | Detail |
| --- | --- | --- | --- | --- |
| U-M9-1 | The time zone preference has no effect, and UTC cannot be chosen | major | M9-03 | Dates use `toLocaleString()` in the browser's zone everywhere. Format with the saved zone (`date-fns-tz` is in the spec). Add "UTC" to the list, since it is the default and Chromium leaves it out, and show friendlier names with search. |
| U-M9-2 | The session list doesn't scale and revoking gives no feedback | minor | M9-04, M9-S3 | 62 rows with raw user agents, no confirmation or success message, and focus lost after a revoke. Add "Sign out all other sessions", parse the browser and OS, show the IP, page or collapse old rows, and move focus to the next row. Check that Last seen is updated. |
| U-M9-3 | The accessibility preset doesn't show what it changed and can leave out high contrast | minor | M9-02 | With an explicit theme the preset keeps it, and the form keeps showing 100% and "On hover" while 125% and always-shown labels are in force. Show the effective values (for example "125% (accessibility mode)"), or ask whether to override the earlier choices. |
| U-M9-4 | Large targets don't apply to form controls | minor | M9-02 | With the preset on, the `/me` selects are 34 px and the checkboxes 13 px; screens.md asks for 44 px in the accessibility preset. |
| U-M9-5 | The previous user's appearance stays on the sign-in page | minor | M9-01 | After sign-out, `regwatch.theme` and the font scale stay on `<html>` and in storage. Reset to the system default on sign-out, or accept this as intended and record it. |
| U-M9-6 | A blank light frame on a device with no stored copy | minor | M9-01 | First paint is light (313 ms) and then dark (339 ms). The spec's cookie mirror read before first paint would cover new browsers too. |
| U-M9-7 | The idle setting's label and the real sign-out time differ by a minute | minor | M9-05 | "15 minutes" signs out at 14, with the warning at 13. Say "about 15 minutes", or describe the one-minute margin. |
