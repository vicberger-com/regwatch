## Data flows touched
- **Reader to API:** `GET /sources` (paged), `GET /sources/{id}/health`, `GET /capture-runs?job_id=` (gate `sources.read`). These return source names, `override_reason`, `last_error`, `error_message`, `error_class` and `robots_decision`, which come from other users or from captured sites.
- **Editor to API:** `POST /sources`, `PATCH /sources/{id}` with `config` from the generated form and `job` (gate `sources.manage`). They also carry `robots_policy` and `override_reason`, which need `sources.override_robots` as well. `DELETE /sources/{id}` and `POST /capture-jobs/{id}/run-now` (gate `sources.manage`).
- **Build time:** `docs/contracts/connectors.yaml` goes through `scripts/gen_connector_forms.py` into `connectors.generated.ts`, and `test_connector_forms.py` compares the two in `make test-api`.
- **Trust boundary:** every string in an API response; the permissions in `/auth/me`, which only steer the UI, because the API checks again.

## Checklist
- [x] Untrusted text rendered as text only: names, `override_reason`, `last_error`, `error_message` and `robots_decision` appear only as JSX children or in `aria-label`, which React escapes. P3 put `<img onerror>` and a `javascript:` link into every one of them: no `img` or `a` element appeared, and the text appeared 7 times, literally.
- [x] Authorization reflected in the UI: the nav link and the route need `sources.read` (`router.tsx:144-157`, `AppShell.tsx:54-56`). Create, Edit, Run now and Disable need `sources.manage`, and the override fieldset needs `sources.override_robots`. Without it the body never carries `robots_policy` or `override_reason` (`SourceEditor.tsx:84-87`; P1's body confirmed this). See finding 1 for a side effect.
- [ ] Form builds a correct config: lists, numbers, booleans, empty strings and defaults are right for the types the form supports. Object fields are not supported, and hidden stored fields are lost (finding 2). Finding 10 covers the gaps in required, enum and length handling.
- [x] Interval against cron: exactly one of `interval_seconds` and `cron` is sent and the other is `null`, which matches `check_job`. The kind is disabled on edit and left out of the PATCH (test). Finding 9 is an edge case.
- [ ] Errors and loading: the list and the save are handled; the runs and health panel shows neither loading nor errors (finding 5).
- [ ] Accessibility conventions: there is one `h1` (AppShell renders none), the controls are labelled, the main table has a caption with the count, and errors use `role="alert"`. The status messages and the runs table's caption fall short (finding 11). `aria-sort` is deferred in BL-92 (d).
- [x] Generator and drift test catch a stale file: in the scratch copy, `--check` returned 1 after a contract change and 1 after a hand edit, and 0 after regenerating. `make test-api` runs the test in CI. It does not catch a contract that parses into the wrong thing (finding 3).
- [ ] Tests show what they claim: what they assert is true, but the risky paths are untested (finding 12).

## Findings
| # | Severity | Description | Fix PR | Verified |

| 1 | medium | **An editor without `sources.override_robots` cannot save any change to most overridden sources, not even a rename.** `SourceEditor.tsx:74-81` always sends `config: fromForm(schema, config)`. `toForm` (`ConnectorFields.tsx:46-62`) pre-fills every contract default, so the config sent back holds keys the stored one may not. The API stores `model_dump(exclude_unset=True)` (`services.py:101-103`). `check_robots` treats any `config` that differs from the stored one as a new override (`services.py:189-193`, `_OVERRIDE_TARGET`) and answers 403. **Failure case:** P1 has an overridden RSS source stored as `{"feed_url": …}`, which is what a source created through the API, a seed or a different client holds. An editor changes only the name, and the UI sends `{"etag_conditional": true, "feed_url": …, "fetch_full_page": true, "max_entries": 100}`. `check_robots` with that config and the editor's permissions raises `403 Overriding robots.txt needs its own permission.`, while the same rename without `config` passes. This breaks the ASSUMPTIONS row "Others with `sources.manage` may edit an overridden source's remaining fields, disable it, and switch it back to `respect`". The UI also offers no way back to `respect` for these editors. It fails closed, so it is not a bypass. **Fix:** send `config` only when the user changed it: compare `fromForm(schema, config)` with `fromForm(schema, toForm(schema, stored))` and leave it out when they are equal. Also give such editors a "Stop overriding robots.txt" control that sends only `robots_policy: "respect"`. Add a test that an editor's rename of an overridden source sends no `config`. | | |
| 2 | medium | **Editing a source erases the config fields the form cannot show.** `api_feed.params` and `field_map` are `type: object` (`connectors.yaml:78,81`). `ConnectorFields` has no object control, so they fall through to a text input (`ConnectorFields.tsx:183-201`). `toForm` turns a stored object into `""` (`:56-59`), and `fromForm` then leaves the field out (`:73-74`). The API replaces `config` as a whole (`services.py:395-396`), so the stored value is deleted. Typing JSON into that input sends a string, which `validate_config` refuses. **Failure case:** P2 has a `generic_json` source with `params: {"q": "cyber"}` and `field_map: {"url": "$.u"}`. The Params input shows `""`. Saving without touching anything sends `config: {"endpoint_url": …, "provider": "generic_json"}`, which removes both, and the connector then has no field map. Any stored key the schema lacks would be lost the same way. **Fix:** start from the stored config and overlay the form: `{...stored, ...fromForm(...)}`, with cleared fields deleted explicitly. Either render `object` fields as a JSON textarea that parses before sending, with an error on bad JSON, or show them read-only with "edit through the API". Add a web test that every property type in `CONNECTORS` is one `ConnectorFields` supports, so a new contract type fails a test and is not turned into a text box. | | |
| 3 | low | **The contract's unquoted descriptions with commas parse into bogus schema keys, and the generator passes them through.** In YAML flow mappings a comma ends the value, so `description: removed before hashing and extraction (dates, counters, navigation)` (`connectors.yaml:9`) becomes `description: "removed … (dates"` plus the keys `counters: null` and `"navigation)": null`. The same happens to `params` (`:78`) and `field_map` (`:81`). They appear as such in `connectors.generated.ts:22,27,73,86`. The hints the UI shows are cut short ("provider-specific query parameters", "generic_json only; maps url"). The drift test cannot notice, because it compares the file with the same misparse. **Fix:** quote those three descriptions in `connectors.yaml` through a contract change. In `render()`, fail on any property value that is `None` or any key that is not a JSON Schema keyword the UI knows (`type`, `format`, `enum`, `default`, `minimum`, `maximum`, `minItems`, `maxItems`, `maxLength`, `items`, `description`), so the next one breaks the build. | | |
| 4 | low | **Every save restarts an interval job's schedule, so a rename triggers a fetch at once.** The job body always carries `interval_seconds` or `cron`, plus `timezone` (`SourceEditor.tsx:66-73`). `reschedule` acts when any `_SCHEDULE` key is present, and sets `next_run_at = now` for interval jobs (`services.py:253-267`). **Failure case:** P1's body has `"job": {"interval_seconds": 1800, "cron": null, "timezone": "UTC", …}` for a name-only change. An editor fixing typos in several sources starts a run of each, and each run fetches from a third-party site. **Fix:** send the schedule keys only when they changed from `current.job`, which needs the same dirty tracking as finding 1. Alternatively the API could reschedule only on a real change, but that API change is out of this scope. | | |
| 5 | low | **The runs and health panel shows no loading state and no errors.** `SourceRuns` renders `health.data` and `runs.data` only (`SourcesPage.tsx:191-199,235`). **Failure case:** in P4 both requests answer 500, and the panel shows only its heading, with no `role="alert"` and no text. A reader cannot tell "no runs" from "the request failed" (or a 403 after a role change). **Fix:** follow `AuditPage.tsx:163-170`. Show "Loading runs…" while `isPending`, and `<p role="alert">{problemText(runs.error, "The runs could not be loaded.")}</p>` on error, likewise for health. | | |
| 6 | low | **Disable is one click with no confirmation, and the screen cannot turn a source back on.** `SourcesPage.tsx:212-223` calls `DELETE /sources/{id}` at once, while the house pattern confirms state changes (`UsersPage.tsx:135,141`, `RolesPage.tsx:115`). Neither the editor nor the panel ever sends `enabled: true`, so undoing a slip needs the API. BL-92 does not list re-enabling. **Fix:** `window.confirm("Disable {name}? Its job stops; items are kept.")`, and an "Enable source" action for disabled sources that sends `{enabled: true, job: {enabled: true}}`. | 7 | low | **Readers cannot close the runs panel.** The Close button is inside the `canManage` block (`SourcesPage.tsx:200-228`), so P4 (a reader) found 0 Close buttons. The only way out is pressing Runs again. **Fix:** render Close outside the `canManage` condition. | | |
| 8 | low | **The editor and the runs panel are siblings with the same React key.** `<SourceEditor key={editing.id}>` and `<SourceRuns key={open.id}>` are both children of the page's `section` (`SourcesPage.tsx:65-74,151-160`). | 9 | low | **A stored interval that is not a whole number of minutes blocks the form.** The minutes field is `String(interval_seconds / 60)` (`SourceEditor.tsx:53-55`) in a number input with the default step of 1 (`:178-186`). In a browser this shows a validation bubble on a field the user did not touch. **Fix:** set `step="any"` (the value is already `Math.round(minutes * 60)`), or show and send seconds. | | |
| 10 | low | **Some contract constraints are lost in the generated form.** The required enum `api_feed.provider` offers a selectable "(default)" (`ConnectorFields.tsx:162`), and the `select` never gets `required` (`:152-160`; only inputs and textareas do). An empty `maximum`-only integer such as `max_entries` accepts `0` and negative values (BL-91 b). The API validates all of these, so this only costs a round trip. **Fix:** add `required` to required selects and leave out the empty option when there is no default. Pass `maxLength` through. The shared alert shows `runNow.error ?? disable.error` (`:230-233`), so after a failed run-now a later failed disable shows the stale run-now message. **Fix:** keep one `<div role="status" aria-live="polite">` mounted and put the messages inside it. ## Checked and found fine
- **Untrusted text:** every untrusted value is a JSX text child or an attribute that React escapes. There is no `dangerouslySetInnerHTML`, `innerHTML`, `href` or `<a>` in `features/sources` (grep). P3 created no element from any field. The REASONS texts are constants, and the run's own `error_message` is shown only when the class is unknown.
- **Permission gating:** the nav and the route need `sources.read`, and a reader sees no Create, Edit, Run now or Disable (test, plus P4). The override fieldset and the robots fields in the body exist only with `sources.override_robots`. An override holder who unchecks the box sends `respect`, which clears the reason on the server. The non-holder's note shows `override_reason` as text.
- **Kind fixed on edit:** the select is disabled and `kind` is left out of the PATCH (test). On create, changing the kind resets the config to the new kind's defaults.
- **Config building for supported types:** lists are split on lines, trimmed and stripped of empty entries. Numbers become numbers, and a non-number is passed on for the API to name. Empty strings are left out so the API's defaults apply, which is correct because the API replaces `config` as a whole. Booleans are always sent. Defaults are pre-filled. A `number` field gets `step="any"` and its minimum (`politeness_delay_seconds`).
- **Schedule:** interval and cron are mutually exclusive in the body, as `check_job` requires. Empty or invalid numbers become `0` or `null` and are refused by the API with a named field, shown through `problemText`.
- **Generator:** the output is deterministic (`sort_keys`), the file is written only to its fixed path, `make connectors` runs it with `-I`, and the generated file is left out of eslint and prettier, so formatting cannot make it differ. The drift test both renders and runs `--check`, and failed on a contract change and on a hand edit in the scratch copy.
- **List and save errors:** the list error and the save error are `role="alert"` with the API's field and message (test). Save is disabled while pending, and Run now while pending or when the source is disabled.
- **Headings and labels:** the page has one `h1` (AppShell renders none), and the editor and panel use `h2`. Every editor control has a label (wrapping or `htmlFor`). The description hints are tied to their controls with `aria-describedby`. The main table's caption includes the count.
